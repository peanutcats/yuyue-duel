# 羽跃对决

侧视 1v1 网页羽毛球对战游戏。纯 HTML5 Canvas + 原生 JS，无需构建、无外部素材，打开即玩，适配电脑与手机。

## 运行

- **直接打开**：双击 `index.html` 即可游玩（快速对战 / 同屏对战 / 自由练习）。
- **本地服务器**（推荐，在线对战的邀请链接需要 http 地址）：
  ```bash
  python3 tools/serve.py
  ```
  然后访问 http://localhost:8765 （开发服务器禁用了缓存；任何静态服务器都可以）。
- **局域网联机**：用电脑运行上面的服务器，手机访问 `http://电脑IP:8765` 即可与电脑上的玩家在线对战。
- **更新版本**：修改 JS/CSS 后把 `index.html` 里的 `?v=3` 加一，避免玩家浏览器缓存旧代码。
- **部署**：整个目录是静态文件，可直接放到 GitHub Pages、Netlify、Vercel、任意 Nginx 等。

## 玩法要点

| 操作 | 键盘 | 触屏 |
| --- | --- | --- |
| 前后移动 | A / D 或 ← / → | 左下滑动条 |
| 起跳 | W / ↑ / 空格 | 跳 |
| 高远球（低位时为挑球） | J 或 Z | 高远 |
| 吊球（近网时为网前轻放） | K 或 X | 吊球 |
| 扣杀（需起跳、足够高度与体力） | L 或 C | 扣杀 |
| 暂停 | Esc / P | 左上角按钮 |

同屏双人：左方 `A D W + F G H`，右方 `← → ↑ + , . /`（或小键盘 1 2 3）。

- **击球判定**：按键后有约 0.17 秒的有效挥拍窗口，最佳时刻约在按键后 0.11 秒。羽毛球必须进入以肩为中心的“甜区圆环”才能击中。太早挥空、太晚过身；位置与时机越准，回球越快越稳。跑动中、低点救球、接杀时回球质量会下降。
- **方向修饰**：击球瞬间按住“向网”方向，高远变平高、吊球变劈吊、扣杀打近；按住“向后”，扣杀打深。
- **体力**：起跳 12、扣杀 24，移动与普通回球不消耗；停止高消耗动作 1 秒后开始恢复，每分结束回满。体力不足时只能低跳，扣杀会变成平抽。
- **规则**：7 分制，需领先 2 分，10:10 后先得 11 分者胜。压线算界内，得分方发球。发球时看头顶力度条，指针越靠中间发球越稳。

## 模式

- **快速对战**：简单 / 普通 / 困难 AI。AI 和玩家的移动、跳跃、体力参数完全相同，难度只影响反应时间、落点判断误差、挥拍时机误差、回位速度和球路选择；普通及以上会读取你连续使用的同类球路并提前站位（屏幕提示“预判！”）。
- **好友对战**
  - 在线：基于 WebRTC（PeerJS），房主权威模拟，好友上传输入、接收 60Hz 快照并插值渲染，对好友的挥拍做了延迟补偿。房主创建房间后把 4 位房间码或邀请链接（`?room=XXXX`）发给好友，好友打开链接会自动加入。
  - 同屏：一台设备两人对战（键盘左右分区；手机横屏两侧各一套按键）。
- **自由练习**：接球 / 高远球 / 吊球 / 跳杀。发球机喂球，显示预计落点（黄圈）、理想站位（青色虚线）、挥拍倒计时圆环与“起跳！/挥拍！”提示，以及落点目标区和失败原因。

## 在线对战说明

- 默认使用 PeerJS 公共信令服务器，组件从 jsDelivr / unpkg 按需加载，需要联网。
- 已配置多组 STUN（含国内可达的 `stun.miwifi.com`、`stun.chat.bilibili.com`）以及 PeerJS 的公共 TURN。若所在网络无法访问公共信令服务，可自建：
  ```bash
  npm install -g peer && peerjs --port 9000 --path /peer
  ```
  然后在 `js/net.js` 的 `YY.NET_CONFIG.peer` 中加入 `host / port / path / secure` 配置。
- **掉线与离开**：任一方切到后台（或锁屏）时会发送“暂时离开”心跳，比赛自动暂停并提示对方等待；超过 1.2 秒收不到对方输入/画面也会暂停并显示倒计时，15 秒仍无数据则判定断线，双方回到菜单。
- **加入失败的提示**：房间码不存在会立即提示；若找到了房间但双方网络（对称 NAT、部分校园网/公司网）无法直连，会明确提示“无法建立点对点连接”，可改用手机热点 / 同一 Wi-Fi，或在 `iceServers` 中配置自己的 TURN 服务器。
- 调试：两个标签页的 URL 都加 `?loopback=1`，即可通过 BroadcastChannel 在同一浏览器内联机，验证联机逻辑而不依赖 WebRTC。

## 代码结构

```
index.html        界面骨架（菜单、结算、帮助等）
css/style.css     界面与触屏按键样式
js/core.js        常量、羽毛球空气阻力物理、弹道求解
js/match.js       比赛逻辑：移动、跳跃、挥拍判定、球路、体力、计分
js/ai.js          击球点求解（AI 与练习提示共用）与三档 AI
js/practice.js    自由练习：发球机与提示
js/render.js      Canvas 渲染：球馆、角色、轨迹、特效、HUD
js/audio.js       WebAudio 合成音效
js/input.js       键盘与触屏输入
js/net.js         在线对战（PeerJS）、快照与好友端插值视图
js/main.js        模式管理、事件反馈、主循环
tools/sim.js           开发用：无界面 AI 对 AI 平衡测试，如 node tools/sim.js normal hard 10
tools/practice_sim.js  开发用：按提示操作的机器人验证各练习可完成
tools/serve.py         开发用：禁用缓存的静态服务器
```

物理以 120Hz 固定步长运行。羽毛球使用二次空气阻力（终端速度约 11 m/s），因此高远球先快后慢、几乎垂直下落，扣杀出手极快但迅速减速。
