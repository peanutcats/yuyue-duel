# 羽跃对决

侧视 1v1 网页羽毛球对战游戏。纯 HTML5 Canvas + 原生 JS，无需构建、无外部素材，打开即玩，适配电脑与手机。

此版本保存在 `codex/server-authority` 分支，在线比赛由独立 Node.js 服务器计算。`main` 分支保留 V9 的 PeerJS + Cloudflare TURN 联机方式，用于 Vercel 生产部署。两种联机协议的房间不互通。

## 运行

在线对战使用 Node.js 22 或更新的受支持 LTS 版本：

```bash
npm ci
npm start
```

打开 http://127.0.0.1:8080 。两位玩家通过「好友对战」创建 / 加入房间。
局域网测试使用 `HOST=0.0.0.0 npm start`，手机打开 `http://电脑IP:8080`。

直接打开 `index.html` 或使用 `python3 tools/serve.py` 仍可进行快速对战、同屏对战、自由练习；在线对战需要 Node 比赛服务。静态网站部署到其他域名时，需要显式配置 `window.YUYUE_SERVER_URL` 为可达的 WSS 地址，并在服务端设置 `ALLOWED_ORIGINS`。

JS/CSS 缓存版本当前为 `?v=10`。部署说明见 [deploy/README.md](deploy/README.md)。

## 玩法要点

| 操作 | 键盘 | 触屏 |
| --- | --- | --- |
| 前后移动 | A / D 或 ← / → | 左下摇杆，短推即可移动 |
| 起跳 | W / ↑ / 空格 | 跳 |
| 高远球（低位时为挑球） | J 或 Z | 高远 |
| 吊球（近网时为网前轻放） | K 或 X | 吊球 |
| 扣杀（需起跳、足够高度与体力） | L 或 C | 扣杀 |
| 暂停 | Esc / P | 左上角按钮 |

同屏双人：左方 `A D W + F G H`，右方 `← → ↑ + , . /`（或小键盘 1 2 3）。

- **击球判定**：按键后有约 0.17 秒的有效挥拍窗口，最佳时刻约在按键后 0.11 秒。羽毛球必须实际过网、球头完全进入己方半场，并进入以肩为中心的“甜区圆环”才能击中；撞网球不能隔网接回。太早挥空、太晚过身；位置与时机越准，回球越快越稳。跑动中、低点救球、接杀时回球质量会下降。
- **方向修饰**：击球瞬间按住“向网”方向，高远变平高、吊球变劈吊、扣杀打近；按住“向后”，扣杀打深。
- **体力**：起跳 12、扣杀 24，移动与普通回球不消耗；停止高消耗动作 1 秒后开始恢复，每分结束回满。体力不足时只能低跳，扣杀会变成平抽。
- **规则**：7 分制，需领先 2 分，10:10 后先得 11 分者胜。压线算界内，得分方发球。发球时看头顶力度条，指针越靠中间发球越稳。

## 美术与表现

- **三座场馆**（菜单中可选或随机，在线对战由创建房间者选择）：
  - 星光体育馆：夜场聚光灯光柱与浮尘、六排可欢呼的观众、闪光灯、滚动 LED 广告板、裁判椅、抛光木地板倒影。
  - 落日天台：黄昏天空与太阳光晕、两层城市天际线与灯窗、飘动的云和飞鸟、随风摆动的串灯、暖光萤火、长投影与镜头光晕。
  - 霓虹电竞场：闪烁霓虹招牌、扫动激光、荧光棒、发光网格地面，球场线会随击球与扣杀脉冲发光。
- **角色**：骨骼姿态（IK 腿 + 两段手臂），分层着色与描边、面部表情、视线跟随羽毛球、马尾 / 头带弹簧摆动；有准备、跑动、起跳、扣杀反弓、低位弓步、得分庆祝与失分沮丧等姿态。击球与发球时拍面精确落在物理接触点上。
- **镜头**：发球时推近发球方，扣杀和救球时冲击推镜并震屏，背景层带视差。
- **特效**：丝带状球迹（扣杀为火焰色）、挥拍光弧、跳杀残影、火花 / 光晕 / 冲击环 / 速度线、落羽、落点光柱与地面波纹、球网波动、得分彩带、胜利彩带雨与场馆联动（观众欢呼、LED 快讯）。
- **界面**：转播风记分牌（头像、体力条、比分弹跳、发球标记、赛点徽章、回合计数）、斜切得分横幅、玻璃质感菜单、场馆缩略图选择、结算页头像与数据对比条。
- **自动画质**：持续掉帧时自动关闭倒影、残影等高开销效果并降低分辨率，流畅后再恢复。

## 模式

- **快速对战**：简单 / 普通 / 困难 AI。AI 和玩家的移动、跳跃、体力参数完全相同，难度只影响反应时间、落点判断误差、挥拍时机误差、回位速度和球路选择；普通及以上会读取你连续使用的同类球路并提前站位（屏幕提示“预判！”）。
- **好友对战**
  - 在线：**服务器权威模式**。双方通过 WebSocket 只上传移动和按键，服务器以 120Hz 统一计算球路、碰撞、体力和比分，30Hz 下发状态。浏览器预测自己的角色运动，并用服务器状态校正；球路与得分只接受服务器结果。4 位房间码或 `?room=XXXX` 邀请链接可加入同一个房间。
  - 同屏：一台设备两人对战（键盘左右分区；手机横屏两侧各一套按键）。
- **自由练习**：接球 / 高远球 / 吊球 / 跳杀。发球机喂球，显示预计落点（黄圈）、理想站位（青色虚线）、挥拍倒计时圆环与“起跳！/挥拍！”提示，以及落点目标区和失败原因。

## 在线对战说明

- Node 服务同时提供网页、`/ws` WebSocket 与 `/healthz` 健康检查。无须 PeerJS 公共信令、STUN 或 TURN。
- 创建者与加入者拥有同等计算权限，创建者关闭浏览器会触发同样的断线等待规则。
- 操作包有递增序号和独立按键编号，服务器校验输入范围、类型、包大小和发送速率，忽略客户端自报的坐标、球速与分数。
- 房间有独立比赛编号与重连令牌。网络暂断后自动尝试重连，服务端保留席位 20 秒；令牌只在当前页面内存中保存，刷新页面需重新建房。任一方切到后台或超过 1.2 秒没有操作同步时，比赛暂停并清空待执行按键。空房间 10 分钟、已结束比赛 2 分钟后回收。
- 再来一局需要双方确认。重开后旧比赛的操作包会被忽略。
- WebSocket 拥塞时合并尚未发送的位置快照并保留事件；持续严重积压时断开后重连，以完整状态恢复。
- 客户端立即预测自己角色的移动、起跳和挥拍动画，但不会预测命中、改变羽毛球轨迹或自行计分。第一版没有历史回溯击球判定；高延迟会影响击球时机，需要选择双方均低延迟可达的服务器。
- 目前房间存放在内存，服务重启会结束正在进行的比赛。默认最多 20 个房间是防止资源耗尽的配置上限，并非容量保证，正式并发容量需要在目标机器上压测。
- 原 PeerJS / Cloudflare TURN 代码暂留作历史回归参考，当前网页入口不使用它们。

## 代码结构

```
index.html        界面骨架（菜单、结算、帮助等）
css/style.css     界面与触屏按键样式
js/core.js        常量、羽毛球空气阻力物理、弹道求解
js/match.js       比赛逻辑：移动、跳跃、挥拍判定、球路、体力、计分
js/ai.js          击球点求解（AI 与练习提示共用）与三档 AI
js/practice.js    自由练习：发球机与提示
js/char.js        角色：骨骼姿态、着色、表情、头像
js/venues.js      场馆：屏幕几何、静态层与动态层（灯光、观众、天气、霓虹）
js/render.js      渲染器：镜头、分层合成、羽毛球与球迹、粒子特效、HUD
js/audio.js       WebAudio 合成音效
js/input.js       键盘与触屏输入
js/net.js         插值显示视图，以及未启用的旧 PeerJS 实现
js/state.js       浏览器 / Node 共用的服务器状态快照
js/server-net.js  WebSocket 客户端、自动重连与角色预测
server/index.js   HTTP / WebSocket 服务、固定步长调度、连接限流
server/rooms.js   房间、输入校验、比赛权威计算、重连和事件
deploy/           systemd 安装脚本与部署说明
js/main.js        模式管理、事件反馈、主循环
tools/sim.js           开发用：无界面 AI 对 AI 平衡测试，如 node tools/sim.js normal hard 10
tools/practice_sim.js  开发用：按提示操作的机器人验证各练习可完成
tools/serve_regression.test.js  发球、球网碰撞、击球显示与联机时序回归测试
tools/serve.py         开发用：禁用缓存的静态服务器（含本地 /api/turn）
tools/turn_api.test.js TURN 凭证接口测试：node --test tools/turn_api.test.js
api/turn.js            Vercel 函数：向 Cloudflare 申请 TURN 临时凭证
```

物理以 120Hz 固定步长运行。羽毛球使用二次空气阻力（终端速度约 11 m/s），因此高远球先快后慢、几乎垂直下落，扣杀出手极快但迅速减速。

运行发球与显示一致性回归：`node --test tools/serve_regression.test.js`。

## 手机横屏与触控

菜单、竖屏提示和对局左上角都提供横屏全屏入口。先立即适配横屏，再申请浏览器全屏与方向锁；不支持时保留 CSS 横屏并明确提示，不能强制隐藏浏览器系统工具栏。支持退出全屏、旋转坐标映射与安全区域。

左手摇杆仅控制左右移动，约 25 像素短推达到全速；上下拖动不会起跳。右下角金色起跳大键为主键，高远、吊球、扣杀沿左侧至上方环绕，独立圆形触区之间留出间隔。支持多指并行，松手、触摸取消、切后台与旋转时自动释放输入。操作区同时使用 touch-action 与非被动 touchend 事件拦截双击缩放，保留每次触摸对应的击球动作；菜单仍使用正常点击，帮助页可滚动。

## 联机验证与延迟

执行 `npm test` 覆盖发球、撞网、碰撞、插值以及服务器操作校验、双方一致性、暂停 / 重连、再来一局、真实 WebSocket 和静态文件访问边界。

界面显示的是当前玩家到比赛服务器的应用层往返时间和画面缓冲。服务器物理固定步长独立于浏览器刷新率；扣杀停顿不会冻结网络时间。换成服务器计算并不能消除网络传输延迟，也不能保证比双方直连更低。

移动触控回归（需 Playwright CLI）：先启动本地服务器并打开游戏，再运行 `mkdir -p output/playwright`，将 `tools/touch_controls.browser.js` 的内容传给 CLI 的 `run-code`。覆盖快速连点防缩放、每次点击仅触发一次、摇杆上下拖动不起跳、左右切换、多指移动加起跳、横屏旋转与环形触区间距；可分别用 Chromium 与 WebKit 执行。
