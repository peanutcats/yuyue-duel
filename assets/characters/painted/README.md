# 羽跃角色位图资源

本套覆盖全部 21 位角色。按用户确认的六人预览画风，通过用户指定的图像 API 调用 `gpt-image-2` 生成，使用 imagegen 技能的 CLI/API 模式；没有在运行时调用生图接口。

每个角色目录包含：

- `portrait.png`：去背景后的全身立绘，最大 576 × 864。
- `avatar.png`：从同一立绘裁切的 256 × 256 头像，没有另行生成一张脸。
- `rig.png`：768 × 1024 动画图集，含正背面头部、上衣、下装、上臂、前臂、握拍手、大小腿、正侧面鞋。
- `hair.png`：五名长发角色的独立发尾图层，位于身体后方。

`manifest.json` 保存图集坐标、角色名称、立绘尺寸、资源分包和原始图 SHA-256。`prompts.json` 保存完整制作提示词，不含 API 密钥。最初六位角色的提示词在项目 `output/imagegen/character-preview-20261114/prompts/` 中；本轮原始生图与修订记录在 `output/imagegen/character-production-20261114/` 中。原图不进入微信资源包。

## 运行时

`js/character-sprites.js` 负责跨平台图片加载、缓存、立绘适配与骨骼贴图绘制。头像异步完成后原位重画缓存 Canvas；角色页预热模型。2D 和纵深球场复用现有运动解算与真实拍面接触点，图片仅改变显示。装备鞋、特殊市场装备与囚服仍保留对应的游戏效果与造型逻辑。

旧矢量资源作为不支持图片的导出环境和特殊换装时的兼容后备保留。正常角色页、头像和对局优先使用本套位图。游戏内仍可自由移动、转身、跳跃、挥拍和使用技能，并非站立图片整体平移。

角色立绘在进入主菜单时以两个并发任务预加载，已解码的 21 张立绘单独保留（约 25 MiB），不与最多六张场内模型图集共用淘汰上限。首次尚未加载完成时显示加载状态，不再先绘制旧矢量人物；图片失败时也不切换画风。微信内存警告会清空图片缓存并取消剩余预加载任务，重新进入角色页可恢复加载。

## 构建

1. 运行 `tools/build-character-bitmaps.py`，准备透明 PNG、头像、图集及 `js/character-sprite-data.js`。依赖 Pillow、numpy、scipy、rembg[cpu]；可用 `--only id1,id2` 更新指定角色。这个步骤仅处理已生成的本地图片，不访问图像 API。
2. 运行 `node tools/export-painted-gallery.js` 更新图鉴。
3. 运行 `npm run build:wechat` 同步共享逻辑和四个 `characters-*` 资源分包，检查包体限制。
